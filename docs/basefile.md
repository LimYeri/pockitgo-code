# **서비스 개요**

## 서비스명

**PockitGo** *— 뽁. 잇. 고.* (뽁 찍고, 잇고, 가자)

---

## 한줄 소개

가고 싶은 곳을 뽁 찍으면, AI가 동선과 일정까지 자동으로 최적화해주는 그룹 여행 플래너 웹앱

---

## 개발 목표

"이번 주말 제주 어때?" 한마디로 시작은 했는데, 막상 계획을 짜려면 막막합니다. 카카오톡 채팅방에서 각자 가고 싶은 곳을 올려도 메시지는 묻히고, 겨우 추린 장소들도 동선이 엉망이라 이동에 시간을 다 씁니다. 막상 도착하면 휴무라 당황한 적도 한두 번이 아닙니다.

**PockitGo는 이 세 가지 문제를 한 번에 해결합니다.**

| 문제 | PockitGo의 해결 |
| --- | --- |
| 장소 의견이 카톡방에서 묻힘 | 여행방 링크 하나로 친구들의 위시리스트를 한곳에 수집 |
| 동선 계획이 너무 오래 걸림 | LangGraph 기반 AI Agent가 운영시간·휴무일·숙소·고정 예약을 모두 고려해 최적 동선 자동 생성 |
| 돌발상황 대응 방법이 없음 | 모든 장소에 플랜 B/C 대안을 미리 제시해 즉흥 대처 없이 바로 이동 |

---

## 타깃 사용자

**"여행은 가고 싶은데 계획 짜는 건 너무 귀찮은 20–30대 그룹"**

- 2–6인 국내 여행을 자주 떠나는 MZ 세대
- 여행지 탐색은 인스타·유튜브·블로그·지도어플로, 공유는 카카오톡으로 하는 사람들
- 동선 고려 없이 짠 계획 때문에 여행 중 이동 시간만 잡아먹어 본 경험이 있는 사람들
- 자차 여행 기준으로 움직이는 그룹

---

## 기대 효과 (사용자 가치)

- **계획 스트레스 제로:** 카톡방 폭탄 없이 링크 하나로 친구들의 위시리스트가 모입니다. 흩어진 장소들이 하나의 동선으로 자동 정리되어 계획에 쏟는 시간을 대폭 줄일 수 있습니다.
- **동선 걱정 없는 여행:** AI가 운영시간·휴무일·숙소 위치·고정 예약 시간을 동시에 고려해 최적 루트를 생성합니다.
- **돌발상황도 준비된 여행:** 모든 스팟에 플랜 B/C가 미리 준비되어 있어, 휴무나 웨이팅이 길어져도 바로 대안으로 이동할 수 있습니다.
- **다같이 만드는 여행:** 내가 찍은 스팟, 친구가 찍은 스팟이 모두 반영된 일정입니다. 모두의 위시리스트가 담긴 여행이 시작됩니다.

# **페이지 구성**

## 페이지 연결 구조

```
[랜딩 페이지]
      │
      ├──────────────────────────────────────┐
      │                                      │
[여행방 생성 페이지]              [여행방 참여 페이지]
      │                                      │
      └──────────────┬───────────────────────┘
                     │
               [여행방 메인]
                     │
          ┌──────────┴──────────┐
          │                     │
  [위시리스트 페이지]    [일정 생성 페이지]
          │                     │
  [장소 검색 모달]      [일정 결과 페이지]
  [숙소·핀 등록]                  │
                       [플랜 B/C 슬라이드]
```

## 페이지별 설명

### 1. 랜딩 페이지

서비스 소개와 함께 여행방 생성 또는 초대 링크로 참여하는 두 가지 진입점을 제공합니다.

- **입력/버튼**: `여행방 만들기` 버튼 → 여행방 생성 페이지 / `초대 링크로 참여하기` 버튼 → 여행방 참여 페이지

---

### 2. 여행방 생성 페이지

여행지·여행 기간·방 이름을 입력해 새로운 여행방을 만드는 페이지입니다.

- **입력/버튼**: 여행지 입력 / 시작일·종료일 선택 / 방 이름 입력 / `만들기` 버튼 → 여행방 생성 후 고유 초대 링크 발급 → 여행방 메인으로 이동

---

### 3. 여행방 참여 페이지

초대 링크로 접속한 친구가 닉네임을 입력하고 여행방에 합류하는 페이지입니다.

- **입력/버튼**: 닉네임 입력창 / `참여하기` 버튼 → 멤버로 등록 후 여행방 메인으로 이동

---

### 4. 여행방 메인

여행방의 전체 현황(여행지·기간·참여 멤버·저장된 장소 수)을 한눈에 보여주는 대시보드입니다.

- **입력/버튼**: `위시리스트 보기` → 위시리스트 페이지 / `일정 생성하기` → 일정 생성 페이지

---

### 5. 위시리스트 페이지

멤버 전원이 저장한 장소를 카테고리(맛집·카페·관광지·숙소·액티비티)별로 보여줍니다.

- **입력/버튼**: `장소 추가` → 지도 검색 모달 / 장소 카드의 ⭐ → 필수 방문 토글 / 📌 → 날짜·시간 지정 고정 핀 등록 / 숙소 → 체크인·아웃 시간 입력

---

### 6. 장소 검색 모달 (위시리스트 내 모달)

지도 API 기반으로 장소를 검색하고 위시리스트에 추가합니다.

- **입력/버튼**: 검색창에 장소명 입력 → 결과 목록 표시 / `저장` 버튼(혹은 pock 버튼) → 카테고리 선택 후 위시리스트에 추가 / 메모 입력창 → 자유 메모 저장

---

### 7. 일정 생성 페이지

일정 자동 생성 전 설정값(하루 활동 시간·숙소 모드 선택)을 확인하고 생성을 시작합니다.

- **입력/버튼**: 활동 가능 시간 조정 / 숙소 확정·미정 모드 선택 / `일정 생성 시작` 버튼 → AI 에이전트 실행 + 진행 상태 실시간 표시(SSE)

---

### 8. 일정 결과 페이지

LangGraph 에이전트가 생성한 날짜별 타임라인과 지도 동선을 함께 보여줍니다.

- **입력/버튼**: 날짜 탭 전환 → 해당 날 일정 표시 / 장소 카드 클릭 → 플랜 B/C 대안 펼치기 / 드래그 앤 드롭 → 방문 순서 수동 조정

---

### 9. 플랜 B/C 상세 (일정 결과 내 슬라이드)

선택한 장소의 대안 2곳을 카드로 보여주고 즉시 교체할 수 있습니다.

- **입력/버튼**: 대안 장소 카드 확인 / `대체` 버튼 → 해당 슬롯 장소 교체 후 일정 재정렬

## 구성 요소 설명

| 구성 요소 | 기술 | 역할 |
| --- | --- | --- |
| **Frontend** | Next.js 16.2 + TypeScript + Tailwind CSS | 사용자 화면 전체 담당. SSE로 일정 생성 진행 상태 실시간 수신 |
| **Supabase DB** | PostgreSQL | 여행방·장소·고정 핀·숙소·일정 데이터 영구 저장 |
| **Supabase Realtime** | WebSocket | 멤버 간 위시리스트 실시간 동기화 (별도 구현 불필요) |
| **Supabase Auth** | JWT 세션 | 닉네임 기반 익명 세션 관리 |
| **FastAPI** | Python | LangGraph 호출 및 SSE 스트리밍 처리 |
| **① Filter Agent** | LangGraph | 여행 날짜 기준 휴무일·운영시간 필터링 및 필수 장소 태깅 |
| **② Planner Agent** | LangGraph | 클러스터링 → 고정 핀·숙소 배치 → TSP 정렬 → 타임라인 생성 → 자체 검증 |
| **③ Alternative Agent** | LangGraph | Planner 완료 후 병렬 실행. 각 장소의 플랜 B/C 탐색 |
| **Kakao Maps API** | REST API | 장소 검색, 좌표 변환, 지도 렌더링 |
| **Kakao Mobility API** | REST API | 장소 간 자차 이동 시간·거리 계산 |
| **배포** | Vercel + Railway | Next.js → Vercel / FastAPI → Railway |

| 구분 | 내용 |
| --- | --- |
| **입력** | 장소 카드의 📌 버튼 클릭 → 날짜·시간 입력 |
| **동작** | SchedulePin 생성 (type: RESERVATION) → 해당 슬롯 잠금 처리 |
| **결과** | 카드에 📌 + 지정 날짜·시간 표시, 일정 생성 시 해당 시간 고정 |

---

## F-06. 숙소 등록

| 구분 | 내용 |
| --- | --- |
| **입력** | 숙소 장소 검색 → 체크인 날짜·시간 / 체크아웃 날짜·시간 입력 |
| **동작** | SchedulePin 생성 (type: STAY) → 날짜 범위로 저장 |
| **결과** | 위시리스트에 숙소 카드 노출, 일정 생성 시 매일 출발·복귀 거점으로 반영 |

---

## F-07. 일정 자동 생성

| 구분 | 내용 |
| --- | --- |
| **입력** | 하루 활동 가능 시간 설정 → `일정 생성 시작` 버튼 클릭 |
| **동작** | LangGraph 3-Agent 실행 (Filter → Planner → Alternative), SSE로 진행 상태 실시간 스트리밍 |
| **결과** | 날짜별 타임라인 + 지도 동선 + 플랜 B/C 생성 완료 |

**Agent별 동작**

| Agent | 입력 | 동작 | 결과 |
| --- | --- | --- | --- |
| ① Filter | 전체 장소 목록 + 여행 날짜 | 운영 불가 장소 분류, 필수 장소 태깅 | 유효 장소 목록 |
| ② Planner | 유효 장소 + 고정 핀 + 숙소 | 클러스터링 → TSP 정렬 → 타임라인 생성 → 자체 검증 | 날짜별 일정 |
| ③ Alternative | 확정된 일정의 각 장소 | Kakao Maps Nearby Search로 반경 내 동일 카테고리 장소 탐색 (병렬 실행) | 장소별 플랜 B/C |

---

## 주요 사용 흐름

## 메인 플로우 — 여행방 생성부터 일정 확인까지

```
[Step 1] 여행방 생성
사용자가 랜딩 페이지에서 여행 제목·여행지·기간을 입력하고 여행방을 생성합니다.
생성 완료 시 고유 초대 링크가 발급되며 여행방 메인으로 이동합니다.
        │
        ▼
[Step 2] 친구 초대
초대 링크를 복사해 친구들에게 공유합니다.
링크로 접속한 친구는 닉네임을 입력하고 여행방에 참여합니다.
참여 즉시 다른 멤버 화면에 실시간으로 반영됩니다.
        │
        ▼
[Step 3] 위시리스트 수집
멤버들이 각자 가고 싶은 장소를 검색해 저장합니다.
꼭 가고 싶은 곳에는 ⭐, 예약된 일정은 📌 날짜·시간과 함께 고정 핀으로 등록합니다.
숙소가 확정된 경우 체크인·아웃 시간과 함께 숙소를 등록합니다.
        │
        ▼
[Step 4] 일정 생성
하루 활동 가능 시간을 설정하고 '일정 생성 시작' 버튼을 누릅니다.
LangGraph 3개 에이전트가 순차·병렬로 실행되며 진행 상태가 실시간으로 표시됩니다.
        │
        ▼
[Step 5] 일정 확인 및 조정
날짜별 타임라인과 지도 동선을 확인합니다.
마음에 들지 않는 장소는 플랜 B/C로 교체하거나 드래그 앤 드롭으로 순서를 조정합니다.
숙소 미등록 시 날짜별 추천 숙소 구역 힌트를 확인하고 직접 예매합니다.
        │
        ▼
[Step 6] 여행 출발
확정된 일정을 보며 여행을 떠납니다.
돌발상황 발생 시 플랜 B/C를 즉시 확인해 대안 장소로 이동합니다.
```
