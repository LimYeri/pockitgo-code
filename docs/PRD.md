# PockitGo MVP PRD

---

## 1. 프로젝트 개요

**목적**: 그룹 여행 시 장소 의견 수집·동선 계획·돌발상황 대응이라는 세 가지 문제를 하나의 웹앱으로 해결한다.

**사용자**: 카카오톡으로 여행 장소를 공유하지만 동선 계획이 귀찮은 20-30대 2-6인 국내 자차 여행 그룹.

**서비스 슬로건**: 가고 싶은 곳을 뽁 찍으면, AI가 동선과 일정까지 자동으로 최적화해주는 그룹 여행 플래너 웹앱

---

## 2. 목표 및 성공 지표

### 목표

| 구분 | 목표 |
|------|------|
| MVP (해커톤) | 여행방 생성/참여 → 위시리스트 수집 → LangGraph 3-Agent 일정 자동 생성 → 플랜 B/C 제공까지 전 흐름 동작 |
| v2 | 모바일 반응형, 일정 공유/내보내기, 장소 투표 기능으로 사용자 편의성 향상 |
| v3 | 자연어 일정 조정, 숙소 추천 연동, React Native 앱으로 서비스 확장 |

### 성공 지표

- 여행방 생성부터 일정 결과 조회까지의 전체 플로우 오류 없이 완료
- LangGraph 3-Agent 일정 생성 평균 응답 시간 60초 이내
- Supabase Realtime을 통한 위시리스트 실시간 동기화 정상 동작
- 플랜 B/C 대안 장소 각 장소당 2개 이상 제공

---

## 3. 사용자 페르소나

> 본 PRD의 시스템 설계 원칙에 따라 페르소나는 핵심 사용자 특성 요약으로만 기술한다.

- 2-6인 국내 여행을 자주 떠나는 MZ 세대 (20-30대)
- 여행지 탐색은 인스타·유튜브·블로그·지도앱으로, 공유는 카카오톡으로 하는 사람들
- 동선 고려 없이 짠 계획으로 이동 시간만 낭비해 본 경험이 있는 그룹
- 자차 여행 기준으로 움직이며 실시간으로 일행과 일정을 조율하는 사람들

## 4. 기능 요구사항

### MVP (해커톤 제출 기준)

| ID | 기능명 | 설명 |
|----|--------|------|
| F-01 | 여행방 생성 | 여행 제목·여행지·시작일·종료일 입력 후 고유 ID 및 초대 링크 발급 |
| F-02 | 여행방 참여 | 초대 링크 접속 후 닉네임 입력으로 멤버 등록, 실시간 반영 |
| F-03 | 장소 검색 및 저장 | Kakao Maps API 기반 검색, 카테고리 지정, 위시리스트 추가 (Supabase Realtime 실시간 동기화) |
| F-04 | 필수 장소 체크 (⭐) | `is_must_visit` 토글, 일정 생성 시 최우선 배치 |
| F-05 | 고정 핀 등록 (📌) | `SchedulePin(RESERVATION)` 생성, 날짜·시간 고정 |
| F-06 | 숙소 등록 | `SchedulePin(STAY)` 생성, 매일 출발·복귀 거점으로 반영 |
| F-07 | 일정 자동 생성 | LangGraph 3-Agent (Filter → Planner → Alternative), SSE로 진행 상태 실시간 스트리밍 |
| F-08 | 일정 결과 조회 | 날짜별 타임라인 + 지도 동선 폴리라인 + 이동 시간 표시 |
| F-09 | 플랜 B/C 확인 및 교체 | 각 장소별 대안 2곳 표시, 교체 시 이동 시간 재계산 |
| F-10 | 일정 수동 조정 | 드래그 앤 드롭으로 방문 순서 변경, 이동 시간 재계산 |

- 예산 관리 기능

## 5. 비기능 요구사항

### 성능

- LangGraph 3-Agent 일정 생성 완료 시간: 목표 60초 이내
- SSE 스트리밍으로 생성 진행률을 실시간 표시하여 체감 대기 시간 최소화
- Supabase Realtime 동기화 지연: 1초 이내

### 가용성 및 배포

- Frontend: Vercel (Next.js 16.2 최적화 환경) — 소스 위치: `frontend/`
- Backend: Railway (FastAPI + LangGraph) — 소스 위치: `backend/`
- 데이터베이스: Supabase (PostgreSQL, 자동 백업 포함)

### 보안

- Supabase Auth JWT 기반 닉네임 익명 세션
- 여행방 접근은 고유 초대 링크(UUID 기반)로만 가능
- Row Level Security(RLS): 여행방 멤버만 해당 방 데이터 접근 허용

### 확장성

- 여행방 1개당 멤버 최대 6명, 장소 최대 50개 기준 설계
- FastAPI 비동기 처리로 다수 일정 생성 요청 동시 처리 가능

## 6. 데이터 모델

### TravelRoom (여행방)

| 필드 | 설명 | 타입/관계 |
|------|------|----------|
| id | 고유 식별자 | UUID (PK) |
| title | 여행방 이름 | TEXT |
| destination | 여행지 | TEXT |

| created_at | 생성 일시 | TIMESTAMP |

### Place (장소)

| 필드 | 설명 | 타입/관계 |
|------|------|----------|
| id | 고유 식별자 | UUID (PK) |
| room_id | 소속 여행방 | → TravelRoom.id |
| name | 장소명 | TEXT |
| lat | 위도 | FLOAT |
| lng | 경도 | FLOAT |
| category | 카테고리 | ENUM (맛집/카페/관광지/숙소/액티비티) |
| is_must_visit | 필수 방문 여부 | BOOLEAN |
| memo | 메모 | TEXT (nullable) |
| added_by | 추가한 멤버 | → Member.id |
| kakao_place_id | 카카오 장소 ID | TEXT |

### Member (멤버)

| 필드 | 설명 | 타입/관계 |

| auth_id | Supabase Auth 세션 ID | TEXT (UNIQUE) |

## 7. API 설계 개요

### Frontend (Next.js) → Backend (FastAPI)

| 메서드 | 엔드포인트 | 설명 |
|--------|-----------|------|
| POST | `/rooms` | 여행방 생성 |
| GET | `/rooms/{room_id}` | 여행방 정보 조회 |
| POST | `/rooms/{room_id}/members` | 멤버 참여 |
| POST | `/rooms/{room_id}/places` | 장소 추가 |
| PATCH | `/rooms/{room_id}/places/{place_id}` | 장소 정보 수정 (필수 여부, 메모 등) |
| DELETE | `/rooms/{room_id}/places/{place_id}` | 장소 삭제 |
| POST | `/rooms/{room_id}/pins` | 고정 핀 / 숙소 등록 |
| DELETE | `/rooms/{room_id}/pins/{pin_id}` | 고정 핀 삭제 |
| POST | `/rooms/{room_id}/itinerary/generate` | 일정 생성 시작 |
| GET | `/rooms/{room_id}/itinerary/stream` | SSE: 일정 생성 진행 상태 스트리밍 |
| GET | `/rooms/{room_id}/itinerary` | 완성된 일정 결과 조회 |
| PATCH | `/rooms/{room_id}/itinerary` | 수동 순서 조정 저장 |
| POST | `/places/{place_id}/replace` | 플랜 B/C로 장소 교체 |

### Frontend → Supabase (직접 호출)

| 기능 | 설명 |
|------|------|
| Supabase Auth | 닉네임 익명 세션 생성 및 JWT 발급 |
| Supabase Realtime | `places` 테이블 변경 이벤트 구독 (위시리스트 실시간 동기화) |

### 외부 API

| API | 사용 목적 |
|-----|---------|
| Kakao Maps REST API | 장소명 검색, 좌표 변환, 지도 렌더링 |
| Kakao Mobility API | 자차 기준 구간 이동 시간·거리 계산 |

## 8. 페이지/화면 명세

### 사용자 여정

```
1. 랜딩 페이지
   ↓ "여행방 만들기" 클릭       ↓ "초대 링크로 참여하기" 클릭

2. 여행방 생성 페이지          2. 여행방 참여 페이지
   여행지/기간/방 이름 입력         닉네임 입력
   "만들기" 클릭                   "참여하기" 클릭
   ↓ 초대 링크 발급               ↓ 멤버 등록

                     3. 여행방 메인
                        여행 현황 대시보드
               ↓ "위시리스트 보기"        ↓ "일정 생성하기"

4. 위시리스트 페이지            5. 일정 생성 페이지
   장소 카드 목록                  활동 시간/숙소 모드 설정
   "장소 추가" → 장소 검색 모달     "일정 생성 시작" 클릭
   ⭐ 필수 체크 / 📌 고정 핀        ↓ SSE 진행 상태 실시간 표시

                     6. 일정 결과 페이지
                        날짜별 타임라인 + 지도 동선
                        장소 카드 클릭 → 플랜 B/C 슬라이드
                        드래그 앤 드롭 → 수동 순서 조정
```

## 9. 예외 처리 규칙

| 상황 | 처리 방법 |
|------|---------|
| 고정 핀 시간 충돌 | 동일 날짜·시간대에 이미 RESERVATION 핀이 존재하면 "해당 시간대에 이미 고정된 일정이 있습니다" 경고 토스트 표시, 등록 차단 후 다른 시간 선택 유도 |
| 전일 휴무 장소 | Filter Agent가 여행 날짜 기간 내 전일 휴무 장소를 자동 제외, 일정 결과 하단에 "방문 불가 장소" 목록 별도 표시 |
| 숙소 미등록 | 일정 생성 진행 가능, Planner Agent는 숙소 없이 동선 최적화 수행, 일정 결과에 날짜별 추천 숙소 구역 힌트 표시 |
| 플랜 B/C 없음 | Alternative Agent가 동일 카테고리 주변 장소 탐색 실패 시 "주변에 대안 장소가 없습니다" 텍스트 표시, 교체 버튼 비활성화 |
| 장소 0개 상태에서 일정 생성 시도 | 일정 생성 버튼 비활성화, "위시리스트에 최소 1개 이상의 장소를 추가해주세요" 안내 |
| SSE 연결 끊김 | 30초 간격으로 자동 재연결 시도, 재연결 실패 시 "일정 생성 중 오류가 발생했습니다. 다시 시도해주세요." 메시지와 재시도 버튼 표시 |
| 닉네임 중복 | 동일 여행방 내 동일 닉네임 입력 시 "이미 사용 중인 닉네임입니다" 오류 표시 |
| 세션 만료 | 재접속 시 초대 링크로 재진입 유도, 세션 복원 실패 시 랜딩 페이지로 리디렉션 |

## 기술 스택 요약

### Frontend
- **Next.js 16.2** (App Router) + **TypeScript** + **Tailwind CSS**
- **Kakao Maps JavaScript SDK** - 지도 렌더링
- **Supabase JS Client** - Auth, Realtime, DB 직접 접근

### Backend
- **FastAPI** (Python) - REST API 및 SSE 스트리밍
- **LangGraph** - 3-Agent 파이프라인 엔진
- **httpx** - Kakao API 비동기 HTTP 클라이언트

### 데이터베이스 & 인증
- **Supabase** - PostgreSQL + Realtime WebSocket + Auth (JWT 익명 세션)

### 외부 API
- **Kakao Maps REST API** - 장소 검색, 좌표 변환
- **Kakao Maps JavaScript SDK** - 지도 렌더링
- **Kakao Mobility API** - 자차 이동 시간·거리 계산

### 배포
- **Vercel** - Next.js Frontend
- **Railway** - FastAPI Backend
